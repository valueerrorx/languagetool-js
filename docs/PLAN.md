## Steps

Line format: `- [ ] Sxx <title> (<arch step>.<n>) | java: <files> | js: <files> | ids: <IDs> | owner | est | status`. Path prefixes: java `core:`/`cli:`/`server:`/`en:`/`de:`/`fr:` = `languagetool-<module>/src/main/java/org/languagetool/` (language modules under `languagetool-language-modules/<code>/`); `Class.java:La-b` = line range of a split class. js paths relative to repo root, `{A,B}` = brace list. Files named by the Java class (PORT-MAP.md).
Every porter step includes the port of the JUnit tests of its classes (Vitest, ARCHITECTURE.md 14) and its `Java:` comments; a step is done when its IDs are covered by passing tests or parity fixtures. `ids: X-...` are pseudo-IDs for helper/lib steps without inventory ID (fixtures under `oracle/cases/X-*`). Steps marked `owner: oracle` extend the harness (oracle/ and scripts/) and sit right before the first step that needs them. A class split into parts edits the same JS file in consecutive steps. Wave-1 todo inventory IDs: each appears in exactly one step (verified by `docs/tools/plan_check.py`).
Oversized data-only classes (CaseRuleAntiPatterns, AgreementRuleAntiPatterns1-3) are split by line range of their pattern tables; mechanical copy, no logic.
