# F15 spec: check pipeline core (JLanguageTool)

IDs: CORE-0050..0053, CORE-0055, CORE-0056, CORE-0070..0083 (docs/inventory/core.md). Java: languagetool-core/src/main/java/org/languagetool/JLanguageTool.java, TextCheckCallable (inner), RuleSet, LevelToneTagCacheKey, SameRuleGroupFilter, Tools#selectRules, CheckResults. JS: src/core/JLanguageTool.js (+ src/core/RuleSet.js, src/core/rules/SameRuleGroupFilter.js, src/core/Tools.js#selectRules).

## Problem
Real rules arrive in F16+ (core rules), F17 (language rule lists), disambiguators F2x, German tagger later. F15 must be verified without them.

## Verification design (oracle X-CHECK-PIPE)
1. Synthetic rules: the Java harness defines a small set of test rule classes (oracle-side, NOT production): SyntheticWordRule(id, subId?, categoryId, regex on token text, message, suggestions, defaultOff, tags e.g. picky, toneTags, goalSpecific, url) and SyntheticTextLevelRule (matches across sentences, minToCheckParagraph) . The JS adapter defines identical JS test rules (test fixtures, allowed). Rules are added with lt.addRule; all built-in rules are excluded by enabledOnly selection (Tools.selectRules useEnabledOnly) so built-in rule lists do not matter.
2. Languages: en-US and fr (taggers ported). de-DE requests are generated but marked for later (German tagger not ported) -> adapter notPorted.
3. Disambiguation: Java runs with its real disambiguator. Synthetic rules match only on token text, so disambiguation does not change matches EXCEPT immunization and token merging (multiword). The harness must ALSO record, per request, whether any token in the analysed sentences was immunized or had readings changed by the disambiguator that the synthetic rules could observe; JS compares only requests where this flag is false, the rest are notPorted until the disambiguation step (adapter reads the flag). Alternative if cheaper: run Java with the disambiguator replaced by a no-op via a Language subclass in the harness (English/French base classes can be subclassed; AmericanEnglish cannot be re-instantiated) — oracle decides and documents.
4. Ops:
   - check2(lang, text|annotatedText parts, mode, level, toneTags, enabled/disabled rules+categories, enabledOnly, motherTongue?) -> matches (ruleId, subId, fullId, from, to, patternFrom/To, line, column, endLine, endColumn, sentence-relative positions, message, shortMessage, suggestions in order, url, type, categoryId) + sentenceRanges + ignore ranges.
   - active-rules: getAllActiveRules ids (order) for enable/disable/category/defaultOff/temp_off/level/toneTag combinations; ignoreRule semantics; selectRules incl. its STDOUT line for temp_off activation.
   - analyze-raw: getRawAnalyzedSentence and getAnalyzedSentence token dumps for en/fr (sentence start token, soft-hyphen removal + position fix, PARA_END) — compare raw always; post-disambiguation only where flag says unchanged.
   Inputs: corpus paragraphs, multi-paragraph texts, \r\n, BOM U+FEFF inside text, soft hyphen, markup via AnnotatedText (incl. interpretAs), very short/empty text, tokenizeText=false, ParagraphHandling ONLYPARA/ONLYNONPARA, all three Modes.
5. Acceptance: all comparable X-CHECK-PIPE requests pass; JUnit subset of JLanguageToolTest / RuleSetTest / SameRuleGroupFilterTest that needs no real rules ported; full parity no regression.

## Out of scope for F15
Result cache (if listed elsewhere), remote rules (DEV-001), multithreading (server step), real rule lists.

## Revision 1 (critic docs/review/F15-critic.md)
R1 Post-check chain (CORE-0087: second ignoreRule pass, LanguageDependentRuleMatchFilter, CleanOverlappingFilter CORE-0187, filterRuleMatchesAfterOverlapping, custom filters; JLanguageTool.java:1178-1198) stays in F35. Harness calls lt.setCleanOverlappingMatches(false) for all X-CHECK-PIPE check requests, and synthetic rule ids are chosen so en/fr filterRuleMatches do not touch them (oracle verifies by also recording the match list before the language filter; if they differ the request is flagged and the adapter marks it notPorted).
R2 New op lt-api: ctor variants incl. NPE messages, getAllRules/getAllActiveRules ids (synthetic only, see R3), getCategories (compare as a set, HashMap order not observable at API level — order only where the API emits it), getPatternRulesByIdAndSubId on synthetic ids, setRules/addRule, sequence mutate -> check -> mutate -> check proving ruleSetCache invalidation (CORE-0053/0077).
R3 Java loads real en/fr built-in + pattern rules. All rule-list comparisons are restricted to synthetic rule ids (filter both sides) or use enabledOnly.
R4 check2 is compared on ALL requests (synthetic rules read token text only). analyze-raw: flag `disambChanged` = (post-disambiguation dump != raw dump, immunization included); raw dump always compared; post dump only when disambChanged=false. Dumps include the preDisambigTokens copy (AnalyzedSentence copyReadings) and the post-disambiguation chunker output (JLanguageTool.java:1774-1779). No Language subclass.
R5 sentenceRanges = plain CheckResults.getSentenceRanges (CORE-0071/0112). Extended ranges (CORE-0084) are F35: recorded by the oracle, adapter marks that field notPorted. Ignore ranges: as Java check2 produces them (porter follows the Java code path); compared as returned.

In: checkCancelledCallback (CORE-0073, harness uses a callback that cancels after N sentences). Out: RuleMatchListener (CORE-0088 -> F35).
R7 JUnit acceptance subset: port every test method of JLanguageToolTest, RuleSetTest, SameRuleGroupFilterTest, CheckResultsTest (if present) that runs without real rules/disambiguators; the porter lists each skipped method with the reason in docs/review/F15-porter.md. Out of scope: ResultCache, SimpleInputSentence cache (F70), remote rules (DEV-001), multithreading (server step).
