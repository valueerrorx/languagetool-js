# F18 spec: language detection

IDs: CORE-0006, CORE-0310..0315, CORE-0317, DE-0176, EN-0177, FR-0176. Java: languagetool-core/.../language/identifier/** (LanguageIdentifier, DefaultLanguageIdentifier, LanguageIdentifierService, SimpleLanguageIdentifier, detector/CommonWordsDetector, detector/UnicodeBasedDetector), LanguageAnnotator, FragmentWithLanguage; Maven dep com.optimaize.languagedetector (sources jar in ~/.m2 or javap). JS: src/core/language/identifier/**, src/lib/optimaize/**.

## Parity target (DEV-006)
The port detects only in-scope languages (wave 1: de, en, fr). Reference = Java's own identifier running with the language set restricted to the in-scope languages, NOT the full-distribution result. Oracle method (in order of preference, documented in docs/review/F18-oracle.md):
 a) restrict Languages' static language list via reflection to the in-scope classes before creating the identifier (so DefaultLanguageIdentifier, optimaize profiles, CommonWordsDetector and UnicodeBasedDetector all see only in-scope languages exactly as Java code builds them);
 b) if a) breaks Java static init (cf. D-035), build the identifier through its real constructors with a filtered profile list and document precisely what differs.
The oracle ALSO records the unrestricted full-set result per request (informational, field `fullSet`), not compared.

## Behaviour to pin
- cleanAndShortenText (URLs, e-mail signatures, @mentions, NBSP, maxLength cut), maxLength < 10 exception text.
- optimaize: n-gram extraction, text filters, short-text algorithm (<= 50 chars), probabilities (Java double arithmetic: emulate exactly where it changes the chosen language or the reported confidence; compare confidence with the existing numeric rules of the comparator), minimal confidence 0.9, profile loading from resources.
- DefaultLanguageIdentifier.detectLanguage(text, noopLangs, preferredLangs[, forcePreferred]) result: language code, confidence, source string ("+fallback", "+prefLang(forced: b)", "+commonwords", "+fallbackToPrefLang" ...), "zz"/noop handling, no-da-if-no rule (keep even though da is out of scope if code path reachable), preferred restriction.
- CommonWordsDetector with de/en/fr common_words.txt (DE-0176, EN-0177, FR-0176).
- UnicodeBasedDetector dominant script codes (pure function, pinned for all scripts, codes are data even if out of scope).
- LanguageIdentifierService factory, canLanguageBeDetected.
- SimpleLanguageIdentifier (CORE-0315) and LanguageAnnotator (CORE-0317): only the parts that work without spellers; speller-dependent paths -> notPorted until the spelling steps (note in PLAN).
- fastText/ngram (remote/ML) paths: DEV-001, not ported.

## Inputs
Corpus paragraphs de/en/fr (whole and truncated to 10/20/30/50/51/100/maxLength chars), rule example sentences, mixed-language texts, texts in out-of-scope languages (es, it, nl, pl, ru, zh, ar, el) -> what the restricted Java says, URLs/e-mails/@mentions/signatures, digits-only, punctuation-only, empty, very long, preferredLangs/noopLangs variants (incl. "zz", out-of-scope codes), forcePreferred true/false.

## Acceptance
X-LANGDETECT all requests pass (language, confidence within comparator rules, source); UnicodeBasedLangIdentifierTest and other identifier JUnit ported; full parity no regression; report detection throughput.
