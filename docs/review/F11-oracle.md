# F11 oracle checkpoint: X-SRX (CORE-0004, CORE-0200, CORE-0201, DE-0022, EN-0022, FR-0021)

Generator: `node oracle/scripts/gen-cases-srx.mjs` (inputs only) -> `oracle/cases/X-SRX/`; fixtures `npm run oracle -- X-SRX` -> `tests/golden/X-SRX/` (8.9 MB, 52 cases). Java ops: `oracle/harness/src/ltjs/oracle/SrxOps.java`. JS adapters `oracle/adapters/{sentence-tokenize,srx-segment,srx-rules}.mjs` are notPorted stubs (F11 must implement them). Comparator: `jsonl` (deep equal). All expected values come from Java (JDK 17, pinned env D-018).

## Ops
- `sentence-tokenize` args `{lang, modes:[bool], texts:[string|null], tokenizer?:"simple"|"srx", srx?}`. Default: `Languages.getLanguageForShortCode(lang).getSentenceTokenizer()` (cached per Language instance, as in production). `tokenizer:"simple"` = `new SimpleSentenceTokenizer()`; `"srx"` = `new SRXSentenceTokenizer(language, srx)`. Result `{class, initialSingleLineBreaksMarksPara, results:[{"false":R,"true":R}]}` keyed by mode (in `modes` order), R = `{sentences:[exact strings incl. whitespace], singleLineBreaksMarksPara}` or `{error:{class,message}}`. For each text and mode the tokenizer is set via `setSingleLineBreaksMarksParagraph(mode)` immediately before `tokenize` (state persists across texts). Op-level failure (tokenizer construction) = error envelope `{ok:false,error}` (case srx-errors id 6).
- `srx-segment` args `{srx:"/segment.srx"|resource path, code:"de_two", texts[]}` -> per text segments[] or `{error}`; whole op `{error}` when the SRX cannot load. Calls package-private `SrxTools.createSrxDocument/tokenize` by reflection (DEFAULT_PATTERN_FLAGS = UNICODE_CHARACTER_CLASS, validation on), i.e. the production engine path. Language code is the full SRX language code (`<shortCode>_two|_one`).
- `srx-rules` args `{srx, codes[]}` -> `{cascade, languageMaps:[[pattern, flags, ruleName]...], byCode:{code:[{name, rules:[[isBreak, before, after]...]}]}}`: pins the parsed SrxDocument (rule order, cascade over all matching maps, pattern strings).

## Cases (case file -> content)
- `edge-<variant>` (14: de-DE, de-AT, de-CH, de-DE-x-simple-language, en-US/GB/AU/CA/NZ/ZA, fr, fr-CA/BE/CH): ~190 edge cases (common + language specific: abbreviations, ordinals "3. Oktober", ellipsis, quotes of all styles, brackets, URLs, e-mail, decimals, initials, \n / \n\n / \r\n / \r, U+2028/2029, NBSP, emoji, non-BMP, lone surrogate, empty, whitespace only, CJK/Arabic/Greek, long inputs) x modes false/true.
- `corpus-<variant>-NN`, `corpus-joined-<variant>`: every paragraph of oracle/corpus/<de|en|fr> (new genuine German corpus) for de-DE, de-AT, de-CH, en-US, en-GB, fr; joined variants = whole corpus joined by blank line / single line break.
- `examples-<de-DE|en-US|fr>-NN`: `<example>` texts of grammar.xml + style.xml (markers/suggestions stripped, entities decoded), all multi-sentence ones plus sampled singles, capped at 1200 per language; `examples-variant-<v>-0`: examples of the variant grammar files (de-CH, de-DE-AT, en-GB, en-US) on that variant.
- `state-<de-DE|en-US|fr>`: initial mode (false = `_two`) and mode switching on the cached tokenizer. `long`: 100k chars without break, 1000-2000 sentences/lines.
- `simple`, `simple-junit`: SimpleSentenceTokenizer (segment-simple.srx, code `xx_two`); not used by any wave-1 check path, only CORE-0201/JUnit. Note it splits after "Dr." (no abbreviation rules).
- `srx-segment-wave1` (de/en/fr x _two/_one), `srx-segment-codes` (other languages, unknown/odd codes -> Default/GeneralImportant fallback, case variants, empty), `srx-segment-simple`, `srx-segment-null` (null code/text), `srx-errors` (missing resource RuntimeException "Path ... not found in class path at ...", directory/non-SRX -> `XmlException: Fatal error parsing SRX`, custom srx for SRXSentenceTokenizer, unknown language zz, pl-PL, null text), `srx-rules`.

## Facts found in Java (for the port)
- All wave-1 variants use the same code: `getShortCode()` = de/en/fr plus `_two`/`_one`; no variant has its own SRX rule name. German/English/French.createDefaultSentenceTokenizer = `new SRXSentenceTokenizer(this)`.
- Default after construction: `_two` (singleLineBreaksMarksPara false). CLI (`Main`) sets it from option `-b`/`isSingleLineBreakMarksParagraph` (both at start and per-detected language); the server never calls the setter (stays false). Both modes are therefore covered.
- Tokenizer instance is cached on the Language, so the mode is shared state (state-* cases).
- Not oracled: nothing; JUnit asserts of SimpleSentenceTokenizerTest / (De|En|Fr)SentenceTokenizerTest are inputs covered by edge/simple-junit but their texts should be ported into tests/ by the porter.
