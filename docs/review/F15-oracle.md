## Synthetic rule specs (SynthRules.java)
Rule ids start with `SYN_` (filter prefix for all list outputs). Common fields: `id`, `subId?` (getSubId; fullId = `id[subId]`), `kind` ("word" default | "text"), `description` (default `"Synthetic " + id`), `message` (default `"msg " + id`), `shortMessage?`, `regex` (java.util.regex), `suggestions:[string]`, `category:{id,name?,defaultOff?,location? (INTERNAL default)}` (-> `new Category(new CategoryId(id), name ?? "Synthetic "+id, location, !defaultOff)`; omitted -> Rule default MISC), `defaultOff` -> setDefaultOff(), `defaultTempOff` -> setDefaultTempOff(), `tags:[Tag names]` -> addTags, `toneTags:[ToneTag names]` -> addToneTags, `goalSpecific` -> setGoalSpecific, `url` -> rule.setUrl and match.setUrl (same URL). In `message`/`shortMessage`/`suggestions`, every literal `{t}` is replaced by the matched text (String.replace).
- word rule `match(sentence)`: `toks = sentence.getTokensWithoutWhitespace()`; for i from 1 (skips SENT_START): `tok = toks[i].getToken()`; skip empty; if `Pattern.matcher(tok).matches()` (full match) emit `new RuleMatch(rule, sentence, toks[i].getStartPos(), toks[i].getEndPos(), message', shortMessage')` (4-arg+short ctor: pattern positions = from/to), then `setSuggestedReplacements(suggestions')` (note: Java does NOT dedupe here; the English language filter later does), url on the match if set. Token text is the soft-hyphen-cleaned token; positions include posFix.
- text rule `match(List<AnalyzedSentence>)`: `all` = concatenation of `sentence.getText()` (start offsets recorded); `Matcher.find()` loop over all, skip empty matches; the sentence for the match = last sentence with start <= match.start; emit `RuleMatch(rule, thatSentence, start+shiftFrom, end+shiftTo, message', shortMessage')` with suggestions'/url as above. `shiftFrom`/`shiftTo` (default 0) exist only to produce invalid offsets. `minToCheckParagraph` (default 0) is returned by minToCheckParagraph(). The 2-arg `match(sentences, annotatedText)` delegates to it.
Standard set `RS` (gen script) uses ids SYN_BAD, SYN_PICKY (tag picky), SYN_SUB[1]/SYN_SUB[2] (same id, overlapping), SYN_OFF (defaultOff), SYN_TEMP (defaultTempOff), SYN_CATOFF (category default-off), SYN_TONE (formal), SYN_CLARITY, SYN_GOAL (persuasive, goalSpecific), SYN_URL, SYN_UNI (unicode classes, uses `\p{So}\p{Cs}`), SYN_SOFT, SYN_TXT and SYN_TXTPARA (text rules). `RS_F` (SYN_DUP, SYN_APOS, SYN_APOS2) only in langfilter cases. Exact definitions: oracle/scripts/gen-cases-checkpipe.mjs (request args carry the full specs, so adapters read them from the request, nothing to copy).

## R6 finding: findLineColumn reachability
`TextCheckCallable#findLineColumn` (JLanguageTool.java:2267) and its error wrapper ("Getting line/column positions failed for match ... Sentence: ...") are NOT reachable with valid rules: any text-level match inside the text finds its sentence. They are reachable only with out-of-range offsets from a (synthetic) rule: toPos > text length -> `StringIndexOutOfBoundsException: begin 0, end 100004, length 8` from `substring` (message is JDK text); negative offsets -> `IndexOutOfBoundsException: Index -1 out of bounds for length 1` from `sentences.get(low - 1)`; fromPos > toPos at construction -> `IllegalArgumentException: fromPos (4) must be less than toPos (0)` from RuleMatch (wrapped by performCheck in `RuntimeException`). Covered by `textlevel-errors-*` (error data: outer RuntimeException message `java.lang.RuntimeException: Getting line/column positions failed for match SYN_TXT_BAD:0-100004:boom Sentence: BOOM now`, cause chain). The JS port can reproduce the wrapper messages; the inner JDK texts (`begin 0, end N, length M`, `Index -1 out of bounds for length 1`) are what Java prints and the comparator checks the top-level message only (inner causes are not compared by check-pipe.mjs), so inner JDK texts are the porter's choice but recommended identical.
