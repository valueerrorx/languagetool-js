## Record per http response
{status, contentType (media type), accessControlAllowOrigin, body (parsed JSON or text)}; optional `expect:"dev006"` / `portLater:true` copied from the request: compareApi skips those responses (record only). status 0 = connection closed without response (/v2/stop). Texts with "Supported language codes are: <list>. The list of languages" are compared with the list cut out (DEV-006).

## How the parity runner must start the JS server (http cases)
Same as the oracle: the runner (oracle/adapters/http.mjs `run(cs, {workDir})`, to be written in F20) must, per case file: create workDir, write cs.files into it, replace `{WORK}` in cs.serverArgs by workDir, pick a free port, start `node bin/lt-server.mjs --port <port> <serverArgs...>` with cwd = repo root, env `LTJS_FIXED_TIME=2026-03-15T10:00:00+01:00 TZ=Europe/Vienna`, poll `GET /v2/healthcheck` until 200, then send cs.requests with oracle/lib/http-run.mjs `doRequest` (exported; same fetch code as the oracle), kill the child at the end. `--stoppable` cases: the process may exit itself; fetch failure must be reported as status 0 (doRequest already does). Return `{responses}` (array). Servers with equal (args, env, files) are shared inside one run; stop and stop-post differ by args for that reason.
cli cases: `node bin/lt-server.mjs <args>` in a fresh workDir with files, stdout/stderr/exit captured (cs.mainClass/jar are Java-only); cases with `stopOnOutput` must be SIGTERMed after the regex appears on stdout.
Required startup lines (stdout, after stripping the timestamp prefix): `WARNING: running in HTTP mode, ...` and `WARNING: running in public mode, ...` (--public only, first), `Setting up thread pool with 10 threads`, `Starting LanguageTool 6.9-SNAPSHOT (build date: X, Y) server on http://localhost:<port>...`, `Server started`; `WARNING: unknown option: <arg>` (+ `- please note ...` suffix for --opt=value) comes first. Failure cases print on stderr `Exception in thread "main" <class>: <message>` (+ `Caused by:`) and exit 1.

## Findings / notes
- detectedLanguage is present for every check, even with explicit language, and comes from detection of the text (e.g. "Cafe naive,, ok." -> sk-SK, "x" -> ca-ES): the port's detector must match on short texts too (F18).
- Java accepts es/pt/ca/nl/ru/ar/zh/ja (DEV-006): recorded, skipped in compare.
- Raw invalid %-escape in a GET query -> 400 text/html "<h1>400 Bad Request</h1>Bad request URI" (JDK HttpServer, DEV-005; the port may answer differently only if content-equal is judged on status+body, here it is compared exactly).
- JSONP (`callback=cb`) body is not JSON: compared as text after buildDate/commit normalisers.
- HEAD /v2/check -> 200 with empty body; OPTIONS /v2/check is handled like a request (400 missing text), no CORS preflight special case.
