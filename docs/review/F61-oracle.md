## UNORACLED / notes
- TestHackHelper.isJUnitTest() branch (year defaults to 2014 when the `year` arg is missing, AbstractDateCheckFilter/AbstractFutureDateFilter/AbstractNewYearDateFilter): decided from the call stack (org.junit.* or PatternRuleTest), so it is never true in the harness. The oracle only records the production branch (current year of the fixed clock). French XML date rules always pass `year`, and fr DateCheckFilter reads tokens by reference; the 2014 branch can only be checked by the JUnit port with setJUnitTest.
- DMYDateCheckFilter: no XML use (rule is commented out); in Java it is effectively broken (it puts the split "dd" "mm" "yyyy" literals into day/month/year, which the parent parses as token references), so every direct request records an error. Reproduced as is.
- FrenchNumberInWordFilter, FindSuggestionsFilter and the Suppress filters depend on the real morfologik speller output (F42, ported) and on the fr tagger/disambiguator (F60); rules-* cases therefore fail until F61 adds the rule list (French#getRelevantRules) and F62 the filter classes.
- Method-level JUnit calls (FrenchRepeatedWordsRuleTest#getRuleMatches with AnnotatedText, CompoundRule abstract helper testAllCompounds) are covered through rule matches only; user-config variants (CompoundRule with a UserConfig, MorfologikFrenchSpellerRule with altLanguages) are not driven. GrammalecteRule / FrenchConfusionProbabilityRule are out of scope (`later` IDs).
- spelling.txt, ignore.txt, prohibit.txt, replace*.txt, synonyms.txt and compounds.txt are read by the generators from resources/ (never printed); regex-pattern entries of compounds.txt were skipped.
- One transient JVM crash ("0 responses") happened once during a full X-FRRULES run under load (other oracle jobs running in parallel); the affected cases were rerun individually and passed. If `npm run oracle -- X-FRRULES` aborts, rerun the missing cases by name.
