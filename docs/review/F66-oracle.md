## Infrastructure added (oracle/ only)
- `oracle/lib/cli-run.mjs`: `occupyPorts` (TCP ports on 127.0.0.1 held open while the program runs: port-in-use, port range cases), safety net `timeoutMs` (default 120 s, SIGKILL; a hung case is recorded with exit "null"). JS twin: `oracle/adapters/cli.mjs` (same `occupyPorts`; `HTTPSServer` is mapped to `bin/lt-https-server.mjs`, NOT PORTED until that file exists).
- `oracle/lib/http-run.mjs`: `{WORK}` is substituted in `files` contents as well as in `serverArgs` (absolute dictionary/confidence/rules paths), case flag `stopAfter` (kill this case's JVM when done, many distinct servers per run). JS twin: `oracle/adapters/http.mjs` (`{WORK}` in files).
- `oracle/lib/http-extra.mjs` (new, used through `doRequest`): request field `localAddress` (client socket bound to e.g. 127.0.0.2: the source address is not in the server's allow-list, the only way to produce SRV-0083 denials locally); request field `hold` (work queue, see below). Plain request records stay `{status, contentType, accessControlAllowOrigin, body}`; a `hold` request yields one record `{status:0, contentType:"group", body:[holder, ...probes sorted by status, body]}`.
- `oracle/comparators/cli.mjs`: option `stderrFilter`; the Java startup race line `Exception in thread "LtThreadPoolExecutorMonitor" ... Label cannot be null` (timer thread before the metrics collector exists, seen in 2 of 126 started servers) is ignored; `Maybe something else is running on that port already?` (second line of the PortBindingException message) is compared together with `Exception in thread`/`Caused by:` lines. `oracle/parity.mjs` passes `stderrFilter`. `oracle/run.mjs`: `ORACLE_CONTINUE`, `ORACLE_AFTER`, `ORACLE_CASES`.
- Ports: only 18100-18199 were used.

## Normalisation (documented, nothing else)
- Timestamps: server stdout lines carry `yyyy-MM-dd HH:mm:ss +0000 ` (UTC of the fixed clock): `stripTimestamp`. Log lines (logback, stderr) are never compared (D-045), only the selected warning/exception lines.
- `buildDate`/`commit` (normalizers, in the "Starting LanguageTool ... (build date: X, Y)" line and `software` JSON), absolute work paths (always normalizer; e.g. "Common words path not found: '/tmp/ltjs-oracle-xxx/dyn/common_words.txt'"), stack frames (`stackFrames`).
- Java stack traces are not compared (only the first `Exception in thread "main" ...` line and the `Caused by:` lines).
- Nothing is normalised in http responses beyond the api comparator rules (software.version/buildDate/commit ignored).

- SRV-0083 IPv6 and `0:0:0:0:0:0:0:1%0` allowed addresses: the server binds IPv4 localhost only; other source addresses are tested with 127.0.0.x.

- SRV-0059 `.dict` (Morfologik) dynamic languages: needs a binary dictionary with `.info`; only `.dic` (Hunspell) was generated. Dynamic language codes without a language-identifier profile (e.g. `xy`) make the Java server fail to start (recorded).

- SRV-0187 prometheus metrics content and SRV-0185 real Redis/Sentinel connections; SRV-0051 real database; premium/login paths (no database).
- SRV-0036 relative `serverURL` forms that Java rejects at the second `URI` parse are recorded as startup failures.
- JVM limitations: privileged port case (`port-privileged`, `port-1`) assume a non-root user.

## Findings
- `workQueueFull` message of non-healthcheck paths is "Error: Error: There are currently too many parallel requests. Please try again later." (doubled prefix), healthcheck "Error: Healthcheck failed: There are currently too many parallel requests."
- X-forwarded-for: the whole first header line is the address ("1.2.3.4, 5.6.7.8" stays one address); header names are case-insensitive; surrounding blanks are removed by the HTTP layer; an empty header value is an address too.
- The allow-list check comes after the limiter, blocked-referrer check and work-queue check; healthcheck is answered before all of them. A denied address still counts for the limiter (429 beats 403 on the second request).
- Unknown-key warnings follow the iteration order of `java.util.Properties` (hash order), not file order.
- `maxTextLength` negative values are accepted: every text, even the empty one, is "too long"; `/v2/maxtextlength` prints the negative number.
- `cacheTTLSeconds=-5` with `cacheSize` starts the config parse but fails at server construction ("duration cannot be negative: -5 SECONDS").
- Dynamic languages with garbage .dic content or a missing .aff file do not stop the server from starting.
- Parity at generation time (sample, one run per case): X-SRV-START PASS args-equals-known, cfg-max-spelling-suggestions-1, port-in-use, port0-range-first-busy, props-equals; FAIL usage-h (usage text), cfg-unknown-keys (warning order), dyn-ok (dynamic languages not ported); NOT PORTED https-h. X-SRV-GUARDS PASS basic-auth, body-hard-50, referrer-blocked, allowlist-denied; FAIL errlimit-basic, error-mapping, forwarded-trusted, limit-count, workqueue-1. The porter works from the failing cases.
- Determinism: X-SRV-GUARDS was generated twice completely (the timeout cases three times): all responses identical after the prewarming fix; 12 X-SRV-START cases re-run: identical compared output (stdout without timestamps, selected stderr lines, exit code).
